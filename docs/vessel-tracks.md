# 船舶历史航线

## 功能与查询口径

历史航线按船舶信息、区域和历史时段查询，在海图上形成独立叠加层。目标可通过 AIS 船型、具体型号、船名、MMSI、IMO 或相关档案信息确定。型号来自系统已经记录的船舶情报对象资料，AIS 船型采用当前船舶档案；查询结果标记这一分类依据。

区域用于选择在所选历史时段经过该区域的船舶，展示范围为这些船在该时段的完整可用轨迹，包含区域以外的航段。每条船、每个时间连续段分别绘制；超过 30 分钟的观测缺口及跨日期线处分段。孤立观测按实际点位表达。

历史查询覆盖近 30 天，单次最长 168 小时，采用 `[from, to)`。一次查询固定时间边界；默认最多 20 艘、每船 500 点，上限为 50 艘、每船 1,000 点，参数乘积最多 10,000 点。结果分别说明候选范围、返回船数、采样及截断，地图缩放和移动保持已生成快照。

## 目标解析与数据依据

- AIS 船型支持精确编码和类别集合，例如货船 70～79、油轮 80～89、客船 60～69、渔船 30。
- 船名、MMSI、IMO、呼号及情报对象名称、别名由后端查找。
- 具体型号从船舶情报对象 `metadata.model`、`metadata.vesselModel`、`metadata.shipClass` 等明确记录匹配。缺少记录时返回实际空结果并提示补充档案；型号与 AIS 船型分别处理。
- 多个明确条件共同限定目标。文字条件经过参数校验与参数化查询，查询和模型投影由受控工具执行。

可向 Agent 发送“绘制当前视野过去24小时货船航线”“绘制型号为052D的船舶过去3天航线”或“绘制 MMSI 413793000 过去24小时航线”。“打开历史航线面板”打开人工条件面板；“关闭历史航线”收起批量轨迹；同一页面的“恢复上次航线”恢复最近展示快照。刷新后可从历史任务点击“在海图展示此航线快照”。

带空格的船名使用引号完整表达，例如 `绘制船名"Ocean Star"过去24小时航线`。船型、型号、名称和 MMSI 可共同筛选；同一文本包含多个独立名称或名称加 IMO 等当前单一文字条件无法完整表达的组合时，Agent 补问后再查询。否定绘制请求进入意图确认。

## 接口与执行边界

共享入口为 `queryVesselTracks(infra, query, context)`，由 HTTP 和 Agent 调用。页面使用 `POST /api/v1/map/vessel-tracks/query`，请求携带现有会话、Origin 与 CSRF。查询输入保存区域、起止时间、selector、来源和资源上限；返回已确定的船舶、分段点位、采样信息、生成时间及查询依据。

后端先解析船舶档案，再根据历史观测筛选候选；来源优选与去重在空间筛选前执行。批量查询按船舶分别分组、分段和抽稀，查询设置超时、内存和输出约束。完整轨迹与标识保留本地，模型只使用批准的统计摘要。

当前每个服务实例持有一个查询槽，档案解析和优选后的原始轨迹读取分别限制 100,000 条；超过上限返回明确的数据量提示。PostgreSQL 查询限时 5 秒，ClickHouse 查询限时 20 秒、内存 512 MiB，外层请求限时 25 秒。取消后等待底层查询收尾才释放查询槽，页面取消与关闭通过展示代次拦截迟到结果。

Agent 通过 `vessel-tracks` Skill 调用本地工具。缺少目标、区域或时间含糊时进入补问；未指定时段时采用最近 24 小时，并在结果中报告绝对起止时间。生成结果按任务版本保存，自动展示经过界面命令领取、绘制与回执确认。关闭清理该批量叠加层并取消相应加载；结果快照保留，可由人员主动恢复。

当前界面命令串行执行，展示等待地图完成的上限为 10 秒；此期间新的 Agent 关闭消息可能等待旧命令收尾。人工“关闭历史航线”和会话切换通过版本变更终止旧展示等待。通用队列的可中断执行按 SDK 浏览器宿主路线推进。

## 发布与回滚

使用追加迁移扩展任务意图与结果字段，既有迁移保留原内容。更新服务前确认无在途写入并按项目入口重启。回退时先停止新航线任务和命令，将在途展示收敛至持久状态；保留追加字段、任务结果和已有业务数据。旧版本对新增状态的读取兼容须在回退前核验。
