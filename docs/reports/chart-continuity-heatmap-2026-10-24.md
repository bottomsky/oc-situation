# 海图连续缩放与热力对齐修复记录

## 问题与根因

滚轮和平移会触发底图状态机进入 loading。旧实现将在线底图和本地区域图的整组透明度设为零，露出全球概略图，待当前视窗加载完成才恢复。MapLibre 已提供父子瓦片保留与按需加载，应用层的整组隐藏破坏了连续显示。浏览器在延迟新级别瓦片的条件下复现了背景透明度为零的旧行为，保留 RED 日志与 trace。

原热力图统计历史时段内的每格去重船数，并将每格计数绘成网格中心的点热点；地图单船层则展示每船最新观测。两种时间口径不同，网格中心的点核绘制还会在放大后产生明显空间偏移。

## 实现

- 在线底图和本地区域图首次呈现后，交互及后继瓦片加载保留已有画面。初次加载与重试按组预热；实际错误或在线超时进入回退，独立图源、有限重试和代次隔离继续生效。
- 当前显示船位密度复用 `vessels` 数据源，每个 point 权重为一，随相同快照、筛选及增量同步，关闭单船图层时同步隐藏。
- 历史时段统计改用实际网格面，裁切到查询区域，保留船数、网格标识和历史版本；日期线、极区和点击命中使用同一几何口径。
- 两种模式互斥展示。智能体历史快照自动切换到历史模式；模式切换撤销范围框选，关闭和迟到请求沿用原代次保护。
- 恢复旧点热图样式时替换为网格面并保持业务图层顺序；精细底图仍呈现的加载过程中持续隐藏本地重复港口标签。

## 验证与运行

验证使用本地自制瓦片和 AIS 夹具，在独立生产构建副本执行浏览器检查。原 API、Web 和工作区 Nuxt 缓存保持独立。

- 全仓单测：`bun run test --maxWorkers=2 --reporter=dot`，181 个文件、1327 项测试通过，耗时 60.92 秒。
- 静态检查：`bun run lint`、根 TypeScript 检查、基于现有 `.nuxt/tsconfig.app.json` 的 Vue 类型检查、所有改动文件 Prettier 检查及 `git diff --check` 通过。
- 隔离 Nuxt 生产构建通过，7 个关键生产源码与构建副本 SHA256 一致。
- 浏览器覆盖 31 个独立场景：原工作台 19、在线底图 4、历史热图 5、UI 回执 2、当前与历史对齐 1。主套件 30 项通过；对齐用例首次执行加载了修正前的测试顺序，错误期待关闭后自动恢复历史结果。保持原有关闭合同，修正测试顺序后单独重跑通过，生产代码保持一致。
- 已检查当前密度与历史网格截图，确认实际船位坐标、筛选更新、模式往返、关闭及 AIS 隐藏联动。延迟后继瓦片期间逐帧检查透明度保持为一，地图实例保持同一个。
- 原 Web（13001）、API（13000）、预测 worker（13111）收尾检查均返回 HTTP 200；仅回收本轮隔离测试服务。

本轮使用本地夹具验证交互与渲染，没有新增公共瓦片批量测试。真实在线图源的可用性仍受网络与数据覆盖影响；当前密度以当前已显示的船位和筛选为准，历史统计保留其固定时间范围。

本机运行证据保留于 `.data/chart-continuity-integration/`，包括单测、构建、浏览器日志、截图、RED trace、源码校验及测试进程回收记录。
