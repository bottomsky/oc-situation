# 个人动态技能交付核验

本轮在现有应用内实现个人技能的自主创建、版本发布、动态加载与原任务续作。通用 SDK 拆包、远程 MCP 和任意代码工具继续按路线图推进。功能入口与配置见[账号动态技能](../agent-dynamic-skills.md)。

## 代码与数据边界

- PostgreSQL 020 追加个人技能目录、不可变版本、目录修订、生命周期幂等记录、任务版本绑定、调用日志和步骤产物。历史迁移保留原文。
- Pi 使用宿主生成的安全目标与输入引用提出候选，最多两次；宿主校验工具、方法、产物与展示覆盖后事务发布并绑定。精确 AIS、私有原文和凭据留在本地。
- 首次任务版本绑定固定工具上限；在途任务、输入修订和默认重试沿用已存版本／上限。新版重试显式形成新尝试。每次调用复核当前权限、技能状态和任务租约。
- 同一任务的船舶、航线、热图与情报分别持久化。步骤展示以产物引用从服务器解析，浏览器回执后继续剩余步骤。人工关闭图层后的迟到展示被拒绝。
- `/skills` 管理当前账号技能与版本；viewer 只读，operator/admin 管理自己。动态开关关闭后保留历史读取。

## 自动化核验

| 核验         | 实际结果与范围                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 全量单元     | 114 文件、837 次执行通过；包含既有重复注册场景，执行次数不表示独立场景数或覆盖率                                            |
| 全量隔离集成 | 29 文件、175 项通过、2 项既有跳过；真实 PostgreSQL、ClickHouse、NATS、S3                                                    |
| 浏览器       | 8 项 API 夹具回归通过；桌面 1920px 和窄屏 390px 截图已检查                                                                  |
| 类型与 lint  | 全工作区 typecheck、ESLint 通过                                                                                             |
| 格式与生成   | 本轮手写文件 Prettier 与 diff 检查通过；OpenAPI JSON 和客户端保留生成器输出样式，离线导出及 openapi-typescript 解析生成成功 |
| 构建         | Web 生产构建，以及 contracts、domain、infrastructure、API、Agent 构建通过；打包后五份内置技能完整性检查通过                 |
| 部署静态检查 | 四组 Compose profile、六个 Kustomize 阶段渲染通过，包含动态技能旗标同步检查                                                 |

真实模型烟测使用 DeepSeek-flash 和独立 PG／CH 合成船舶夹具。首次仅请求模型 1 次，自动生成、发布并加载技能，形成 3 类真实查询产物，通过受控语义客户端的 2 次 UI 回执完成原任务；第二次绑定同一不可变版本，模型调用为 0，同样完成 3 类产物与 2 次回执。出站安全投影断言通过，烟测后随机账号、版本、任务及夹具清理完成。该烟测使用受控语义客户端；浏览器布局与交互由上表 API 夹具回归分别验证。新增浏览器用例使用真实 `useAgentUi` 消费者连续展示航线与热图，验证两个步骤各自的 executing／succeeded 回执和产物身份；新产物缺少服务器投影时返回 UNAVAILABLE，已有图层保持原快照。

首轮全量隔离集成曾有 10 项失败：早期调试残留船位导致三个旧用例出现额外命中，独立 S3 尚未完整初始化导致七项归档检查失败。随后仅重建本轮验证项目，执行正式迁移／消费者／对象存储初始化，再运行全量集成，取得上表结果。

隔离数据库使用专属 Compose 项目 `ais-dynamic-skill-verify`，端口 15433／18124／14223／19001，与业务演示的数据卷和端口分离。测试使用随机账号与来源，并清理各自数据。

## 开发者复核入口

- `apps/agent/dynamic-runtime.integration.test.ts`：真实 PostgreSQL、ClickHouse 与 `processAgentTask`，受控 Pi 候选，跨 worker 两次 UI 回执续作、三产物、二次复用、未知目标回答和精确技能选择。
- `packages/infrastructure/dynamic-skills.integration.test.ts`：CAS、幂等、归属、版本、授权、失租、不可变记录、候选回答、时间补问、历史修订与 UI 版本保护。
- `tests/e2e/skills-workbench.spec.ts`：API 夹具下的管理页面、幂等、冲突、账号切换、产物与技能选择补问。
- `apps/api/src/common.test.ts`：递归 JSON 文档导出与生成客户端可解析性；运行时 JSON 校验保持有效。

读取历史修订使用 `GET /api/v1/agent/tasks/:id?inputRevision=0`；它与旧的 `resultVersion` 参数互斥。所有读取继续限制当前账号所有权。海图默认只呈现当前修订，历史读取本身不触发图层恢复。
