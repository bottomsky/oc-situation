# 海事 GIS 与船舶概率预测交付验证

## 交付能力

海图采用版本化自托管 OSM 资源，提供深浅样式、比例尺、经纬网、测距、区域查询、重叠船舶选择及按需标识。船位在全部缩放级别保持单船身份，通过完整快照分页与有序增量更新；快照释放、到期、容量和背压均有明确处理。

单船、批量和证据航迹采用统一时间／航速配色、连续方向箭头及起终点、停留和转向标记，观测缺口和日期线保持分段。

`vessel-reachability` 与 `navigation-warning-impact` 接入既有专题运行、租约、修订和证据机制。每账号最多持续关注 20 艘船；预测使用独立 worker、2048 条可复现路径和整段精细避陆，分别输出未来位置与沿途经过概率。公告计算使用最新审核版本、精确适用范围、有效时段和船舶条件。预测输入、模型、海岸数据与产物修订固定引用，历史视图按快照保留。

模型版本为 `recent-motion-residual-mc-v1.1`。转向率使用保留方向样本的实际时间差；回测模型和匀速匀向基线共用清洗观测。概率持续标记为未校准，独立真实航次的效果评估支持通过回测命令执行。使用说明见[海事 GIS 与概率预测](../maritime-gis.md)。

新增预测 worker 已接入本地 demo、生产 Compose 和 Kubernetes 共享应用清单，指标端口为 13111，生产资源上限为 2 CPU／2 GiB。部署检查覆盖专用运行模式、探针、Service、监控和各阶段镜像引用；本轮完成静态渲染验证，集群发布由部署流程执行。

## 五万船位性能

环境为 Windows 11、Intel Core i7-14650HX、24 逻辑 CPU、约 32 GiB 内存、1920×1080，Chromium 153.0.8010.12。浏览器使用明确标识的合成压力船位、1000 条分页和本地 HTTP；渲染器从实际 WebGL 信息读取。

| 环境                                         | 完整数据 | 首次实际绘制 | 拖动 FPS | P95 帧时间 | JS 堆      |
| -------------------------------------------- | -------- | ------------ | -------- | ---------- | ---------- |
| 最终生产包、RTX 4060／D3D11                  | 1649 ms  | 4694 ms      | 58.46    | 16.8 ms    | 约 131 MB  |
| 最后视觉调整前的生产包、SwiftShader 软件渲染 | 5449 ms  | 11549 ms     | 14.87    | 283.3 ms   | 约 91.7 MB |

硬件环境达到首次绘制 5 秒及拖动 30 FPS 目标。软件渲染的五万船位性能仍低于目标，密集船位场景需要浏览器启用硬件加速。浏览器诊断默认关闭，验收通过 `?mapDiagnostics=1` 进行有界屏幕采样和按图源修订计数，保持全部身份数据。

另以现有 PostgreSQL 历史数据做只读查询：53183 个身份、54 页、唯一身份与 total 相等，首个查询约 607.85 毫秒，全部本地分页约 624.63 毫秒。这项数据层测量与浏览器首屏耗时分别记录。

## 既有集成问题

完整集成中的 3 项失败集中在 `tests/integration/agent-pipeline.integration.test.ts`：两项会话记忆标识过滤断言，以及一项调用预算续跑断言。

已将原提交 `eb31b175978f22c556c93abacf8709f53ed7c215` 解到独立临时树、离线安装其依赖，确认 `@ais` 模块解析与关键源码校验值均来自原提交，再通过该树原有隔离入口运行同文件。结果为同样的 3 项失败、5 项通过；测试名称与错误一致。本轮保留原断言，后续 Agent 记忆与预算修复可沿该基线单独推进。
