# 外部情报入库与 AI 检索

## 已实现链路

`apps/intelligence` 定时获取公开来源，原始响应归档至 S3，事件及修订保存至 PostgreSQL。Agent 通过本地工具检索、读取并冻结证据，回复中的 `[I1]` 可打开对应任务、输入版本和结果版本的来源卡片。提问与追问不会触发外部采集。

使用 `AGENT_ENABLED=true` 及既有 DeepSeek 服务端配置。情报来源在“情报管理”页面管理；来源可见性默认 `internal`，仅明确配置为 `public` 的标题和脱敏摘要可外发。修改公开性后每次模型调用会复核，凭证、私有原文、船舶标识和精确坐标不进入模型投影。模型输出不能指定 SQL、URL 或联网工具。

## 存储与迁移

迁移 `015_postgres.sql` 添加 `pg_trgm` 搜索文本与分类/时间索引、`intelligence_ingestion_runs`、海况快照、引用 pin 和原文清理账本。`016_postgres.sql` 添加独立 Agent 情报结果及消息的版本绑定。通过 `scripts/workspace.ts migrate` 或 `start.ps1` 按既有迁移顺序执行，需要数据库账号具有创建 `pg_trgm` 扩展权限。

复用 `intelligence_sources/events/archives/relations/reviews`。内容不变复用版本，变化形成修订；撤回和拒绝记录默认排除。公告、新闻、灾害及修订长期保存。每小时仅清理 90 天前未被引用的海况快照及其独占原文，已引用数据受 pin 保护，S3 清理失败可从账本重试，不清理共享桶里的长期情报。

## 检索与引用

`GET /api/v1/intelligence/search` 支持 keyword、sourceIds、category、reviewStatus、timeMode、from/to、bbox、objectId、mmsis、kind、samplePointId 和 forecastFrom/To。默认最近 7 天、最新修订，分页上限 50，读取事务超时 8 秒；游标绑定查询条件和快照时间。管理列表保留原分页接口，共用文本检索逻辑。历史情报查询不继承 AIS 的 168 小时限制。

排序首先考虑标题和正文相关性，再对有来源或对象几何落在中国近海优先矩形 `(105,3,135,45)` 的记录加权。该矩形只用于展示优先级，不能作为影响范围；没有位置的新闻不会由地名推造坐标。

固定工具为 `search_intelligence`、`read_intelligence`、`read_marine_forecast`、`get_intelligence_source_status`。默认 20 条候选，最多 50 条。具体回复必须引用本次已读取的证据；未知引用、未读引用和跨任务引用不能发布。旧消息按其保存的结果版本读取，不随新采集或审核改变。解释追问使用原快照，新条件建立新查询。私有资料只在本地展示。

发布时间、来源观测/更新时间、发生或适用时间、采集时间分别展示。USGS 的 updated 不能称为发布时间；GDELT 索引时间不能称为发生时间。海事有效期未核实时不作为确定适用时间。缺位置新闻显示原因；仅提及地名显示“提及线索”，没有几何不自动标绘。待审核记录可引用，但不能认定航行限制或实际船舶影响。灾害中心和震中均不代表影响范围。

可提问“最近有什么航运事故”“东海近期有哪些航行警告”“当前视野的相关情报”“明天东海代表点浪高”。模糊关键词或时间通过现有条件弹窗补充，同任务自动续作。空结果明确为本地库未检索到，同时显示来源状态和覆盖限制。

命名港口、航道、区域和设施先匹配已登记名称及别名，较具体的名称优先于其包含的通用名称。唯一匹配绑定本地对象，多个匹配在条件框中显示持久化候选供选择；提交再次校验候选归属与对象存在性。固定海域别名同时支持粗范围和文字提及，两者在来源卡分别说明。

## 验证

本机实时采集、真实模型、隔离测试及当前故障见[验收记录](intelligence-search-validation.md)。

契约、运行时、采集解析、检索和前端均有单测；隔离 PostgreSQL、S3、JetStream 集成验证真实入库、去重修订、清理 pin、中文英文检索、索引计划、权限变化、任务恢复及本地工具闭环。浏览器验证使用真实本地 API 与 worker，模型替身和真实 DeepSeek 联调分别记录。实时来源状态以管理页面为准，故障不由缓存或模拟数据冒充成功。
