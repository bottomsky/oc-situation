# 海上智能态势与筹划分析产品方案

## 产品定位

海上智能态势与筹划分析产品面向海上业务筹划、专题研判与持续观察，围绕用户关注的问题、正在发生的事件和长期监控任务，主动组织多源数据分析，形成对当前态势、未来变化及其业务影响的判断，为筹划方案的形成、比较与调整提供依据。

产品以分析任务组织工作，以可追溯的分析结论交付价值。系统根据任务目标主动确定分析步骤，关联有关对象、事件与历史记录，识别影响因素，提出结论和可供比较的筹划选项。用户能够从结论逐层查看相关统计、分析条件和原始数据，并在补充信息或调整条件后继续分析。

“面向未来”体现在对未来时间窗口的趋势研判、条件变化下的影响分析，以及对既有判断的持续验证。产品支持用户提前识别可能影响安排的变化，比较不同条件下的选择，并随着新证据到来修订判断。未来判断以明确的时间范围、成立条件和证据充分程度表达。

产品围绕三类态势分析方式展开：主动询问的态势分析、事件触发的态势分析、长期监控的态势分析。三类方式共享分析能力、证据记录和结论版本，贯通问题提出、分析判断、筹划应用与持续验证。本文描述产品定位与目标能力，建设范围通过具体业务场景进一步细化。

## 服务对象与筹划价值

筹划与分析人员是产品的核心使用者。他们围绕重点区域、船舶、港口、航线、企业及相关事件，提出分析问题、比较可能情景、检查结论依据，并形成供讨论和决策使用的筹划意见。

决策与管理人员主要使用态势摘要、关键结论和选项比较，了解需要关注的变化、潜在影响及其依据。业务专家参与重要结论复核，补充业务约束、修订关联和评价分析结果。数据与系统管理人员负责信息源、数据质量、权限和运行保障，为持续分析提供支撑。

产品重点帮助用户回答以下问题：

- 当前态势的关键特征是什么，哪些变化与本次筹划目标有关？
- 在关注的未来时间窗口内，可能出现哪些变化，判断依赖什么条件？
- 某个事件会影响哪些对象和安排，影响可能何时出现？
- 如果条件发生变化，原有判断和筹划选项将如何调整？
- 当前有哪些可选安排，各自的适用条件、预期影响和主要风险是什么？
- 这些结论依据哪些数据，后续出现什么信号时需要重新判断？

## 三类态势分析模式

### 主动询问的态势分析

用户通过自然语言提出问题或创建专题任务，系统主动组织分析。问题可以针对当前态势，也可以围绕未来安排、变化原因或不同选择展开。系统识别问题中的对象、区域、时间窗口、筹划目标和约束；对影响结论的缺失条件进行针对性询问，并说明当前采用的假设。

分析从问题出发，检索相关资料、检查数据新鲜度与完整性，关联船舶活动、港口情况、通告和已接入的业务信息。系统根据需要开展历史比较、变化分析、趋势研判或条件推演，形成对问题的直接回答，并给出相应依据和筹划参考。

结果按结论、依据、影响和可选安排组织。用户可以继续追问某条结论、补充材料、调整时间范围或修改假设，系统沿用相关任务背景，重新评估受影响的判断。需要持续关注的问题可以转为长期监控任务。

示意场景：用户询问“下周到港应优先安排哪个时间窗口”。在具备相应数据的条件下，系统结合到港计划、当前等泊情况和港口通告，比较候选窗口，说明推荐顺序及其依据，并列出通告有效期、计划完整性等影响判断的条件。

### 事件触发的态势分析

系统根据已配置的关注范围和触发规则，在重要事件出现或状态发生变化时主动启动分析。事件可以来自公开通告、业务系统、人工录入或数据变化识别。触发规则明确对象、条件、重要程度与结果接收范围。

系统核对事件来源、发生时间、有效范围和关联对象，将其与当前分析任务、业务安排和历史情况联系起来，研判发生了什么、影响到谁、影响可能何时出现，以及哪些筹划条件需要重新评估。对尚未核实的事件保留相应状态，使用条件化方式说明潜在影响。

输出形成事件分析结论，包含事件要点、影响对象、时间窗口、可能演变、筹划建议和后续关注条件。用户接收到的是围绕事件形成的分析结果。相同事件的多源报道和后续更新归入同一分析记录，新的证据促使相关结论更新。

示意场景：某港口发布临时限制大型船舶靠泊的通告。系统识别与限制时段重叠的已关注航次，分析对当前到港安排的影响，提出调整到港窗口或进一步核实替代港条件的建议，并关联通告原文、适用条款及采用的航次记录。

### 长期监控的态势分析

用户围绕长期关注的问题建立监控任务，明确对象、区域、观察指标、基线周期、复核节奏和重要变化条件。系统持续积累数据与分析记录，维护当前判断，并跟踪支持判断的关键条件是否发生变化。

系统建立具有适用范围的观察基线，持续比较新数据与历史情况，结合数据质量区分短时波动、持续变化和观测缺口。每轮分析检查已有判断是否仍然成立，识别逐步累积的压力或新的发展方向。基线调整时保留调整依据和版本，持续关注原有异常的后续变化。

输出是一份持续更新的态势研判档案，包含当前结论、趋势依据、重要变化、历史版本和下一次复核条件。出现足以改变判断或影响筹划的变化时，系统主动说明变化内容、原因和业务影响，并提示相关人员；状态稳定时保留观察记录，按约定周期汇总。任务支持调整、暂停和结束。

示意场景：持续观察某区域港口群的拥堵变化。系统比较各港口等泊情况与适用的历史基线，跟踪压力是否由单港扩展至周边港口。当新证据支持区域压力正在累积时，更新对后续到港安排的判断，列出受影响窗口和需要进一步核实的调整条件。

### 三类模式的协同关系

| 分析模式 | 启动方式 | 主要交付 | 持续衔接 |
| --- | --- | --- | --- |
| 主动询问 | 用户提出问题或专题任务 | 问题结论、依据和筹划选项 | 追问、条件调整、转为监控 |
| 事件触发 | 事件出现或满足触发条件 | 事件影响判断与调整建议 | 跟踪事件进展、更新相关任务 |
| 长期监控 | 建立持续观察任务 | 当前研判、趋势变化与结论更新 | 重要变化转为事件或专题分析 |

## 主动分析与筹划支撑机制

### 围绕任务主动组织分析

三类入口进入统一的分析过程：明确任务，组织证据，分析判断，形成结论，支撑筹划，跟踪验证。系统根据问题类型选择适用的分析方法，主动完成资料检索、对象关联、统计比较和证据核对；对关键缺口提出补充信息要求，并记录任务进度与当前可形成的判断。

分析任务保留目标、范围、采用的数据、关键假设、过程结果和结论版本。用户能够查看分析使用的材料和方法摘要，了解结论形成的业务依据，并对其中的对象、条件或结果继续追问。

### 从当前判断延伸到未来研判

态势理解负责说明当前关键特征、近期变化和与筹划目标有关的影响因素。趋势研判结合历史变化、当前状态和已知事件，分析未来时间窗口内可能的发展方向，列出可观测信号、成立条件和需要重新评估的因素。

存在多种合理发展方向时，系统组织可比较的情景，说明各情景依赖的条件及支持程度。资料尚不足以支持某项未来判断时，系统明确当前能够确定的范围、证据缺口和补充验证路径，使结论的适用程度清楚可见。

### 支持条件推演与筹划选项比较

用户可以调整事件持续时间、到港安排、资源条件或其他已明确的业务约束，观察条件变化如何影响态势判断。系统保留共同条件，列出发生变化的假设，比较各情景下的影响对象、时间窗口与主要风险。

筹划选项围绕用户明确的目标与约束提出。系统按一致口径说明各选项的适用条件、预期影响、所需资源、关键风险和待核实事项；给出排序时，同时说明采用的比较标准。业务人员负责方案取舍与决策，产品保留选择依据，并将影响方案成立的条件纳入后续观察。

### 根据新证据更新判断

事件更新、数据修正、用户补充条件和长期监控发现的新变化，都可以触发相关结论复核。系统识别受影响的任务与判断，生成新版本，说明哪些结论得到加强、哪些发生调整，以及调整所依据的证据。

后续实际情况与此前判断进行对照，形成可复盘的分析记录。人工复核意见作为单独记录保存，经过确认的修订进入任务和关联信息管理，使分析经验能够支持后续同类任务。

## 分析结论与数据溯源

### 以结论作为主要业务输出

每次分析围绕具体问题交付明确判断，说明当前结论、未来可能变化、业务影响和可选安排。结论同时标明适用对象、区域、时间范围、关键条件和证据充分程度。用户先理解分析结果，再按需要进入地图、轨迹、事件时间线和原始资料查看依据。

分析结果中的内容按性质分别呈现，帮助用户判断其使用方式。

| 内容类型 | 表达内容 | 配套依据 |
| --- | --- | --- |
| 观察事实 | 原始记录记载的情况与可核实变化 | 来源、具体记录、观测或发生时间 |
| 计算结果 | 汇总、比较和识别得到的结果 | 数据范围、统计口径、计算或识别方法 |
| 分析判断与趋势推演 | 对变化原因、影响和未来发展的判断 | 支持及冲突证据、关键假设、适用条件 |
| 筹划建议 | 围绕业务目标提出的备选安排 | 对应结论、比较标准、约束与预期影响 |

### 从关键判断定位到原始证据

每条关键结论关联具体证据条目。结构化数据可以定位到原始记录及字段，文本资料可以定位到正文片段或原文位置，船舶活动可以定位到相关轨迹区间。证据保留来源标识、发生或观测时间、发布时间、采集时间和内容版本；按数据类型记录适用的时间字段。

对统计或模型分析形成的结论，继续提供参与分析的数据范围、统计口径、方法及版本、关键参数或假设，以及异常和缺失数据的处理说明。产品形成“结论—分析结果—数据范围与处理口径—原始证据”的溯源关系，支撑逐层复核。

源材料的留存方式遵循其授权条件，可以保留获准存储的内容快照、原始记录标识或访问定位。采用定位方式时，明确原文可访问状态及留存限制。来源修订或链接失效时，保留已形成的证据关联与状态记录。

### 说明证据充分程度和判断条件

系统根据来源质量、数据覆盖、时效性、一致性和关键证据缺口说明结论的支持程度。存在冲突材料时，呈现冲突内容及其对判断的影响；多篇转述同一原始消息时，保留共同来源关系。需要量化置信程度的场景，应同时提供可检验的计算或校准依据。

面向未来的结论明确假设、适用时间窗口和失效条件。当前证据只能支持局部判断时，系统交付相应范围内的结论，并列出需要补证的部分。用户能够区分已经得到证据支持的内容和仍需验证的条件推演。

### 保留结论版本与复核记录

系统保留每次结论对应的数据和证据版本，记录新增材料、数据更正、条件变化或人工复核带来的调整。用户可以查看当时采用的依据，也可以比较当前判断与历史判断的差异。

人员补充证据、修正关联或调整结论时，记录操作人、时间、理由和影响范围。基于某个版本形成的简报或筹划材料保留该版本的引用关系，便于复核当时的判断基础。

## 产品能力构成

产品按分析工作组织能力。用户从问题、事件或监控任务进入，在统一工作台获取结论、查看证据、调整条件和继续分析。海上态势地图承担空间理解与结果解释，船舶轨迹、对象档案和事件时间线提供相应分析上下文。

| 能力组成 | 主要职责 |
| --- | --- |
| 分析工作台 | 接收问题，管理任务，呈现结论，支持追问、条件调整和专题分析 |
| 事件分析与长期监控 | 管理触发条件、观察基线和监控任务，主动发起分析并传递重要结论更新 |
| 智能分析与筹划支撑 | 组织证据，开展统计比较、趋势研判、条件推演和筹划选项比较 |
| 态势与对象分析 | 通过地图、轨迹、对象档案和事件时间线，呈现空间、活动及关联信息 |
| 多源数据与证据管理 | 管理信息源、采集与导入、质量状态、对象关联、证据定位及数据版本 |
| 结论与分析成果管理 | 管理结论版本、依据引用、人工复核、专题简报和历史分析案例 |
| 运行与权限管理 | 管理访问范围、凭证、处理记录、任务运行、备份和恢复 |

数据能力按筹划场景组织。AIS、船舶资料、港口与航线信息、授权情报以及业务计划等来源，根据实际接入和授权情况纳入分析，并保留覆盖范围、更新时间与使用限制。源数据权限同步作用于分析结果、引用证据和导出材料。

系统在授权的数据源、分析工具和任务范围内主动开展分析。涉及业务安排的执行由相应业务流程承接，产品负责提供分析结论、比较依据与后续观察条件。

## 产品效果评价

产品效果围绕实际筹划任务评价，重点考察系统能否主动形成有依据、可使用、可更新的判断。验证场景同时覆盖用户询问、事件触发和长期监控，并纳入数据缺失、证据冲突及条件变化等情况。

| 评价维度 | 核心观察点 |
| --- | --- |
| 主动分析 | 能否围绕任务组织所需分析，事件和重要变化出现后能否主动启动研判 |
| 结论价值 | 是否直接回答业务问题，并说明影响、条件与筹划选项 |
| 未来研判 | 是否围绕未来窗口给出有条件的判断，并支持情景比较与后续验证 |
| 数据溯源 | 关键判断是否能够定位到原始证据、数据范围与分析口径 |
| 持续更新 | 新证据能否推动相关结论复核，变化原因与历史版本是否清楚 |
| 业务复核 | 用户能否检查依据、补充条件、修订关联，并复盘判断与实际情况的差异 |

通过真实业务案例积累评价记录，逐步明确分析质量、触发有效性、响应时效和筹划使用效果的衡量口径，为产品能力完善提供依据。
